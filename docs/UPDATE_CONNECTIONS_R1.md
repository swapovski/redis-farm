# Redis Farm 0.2.0 — обновление исходников connections-r1

Это **архив наложения на репозиторий**, не самостоятельная полная поставка и не автоматическая установка на сервер. Версия приложения остаётся `0.2.0`. Ревизия обновления — `connections-r1`.

## Что включено

- Общий Redis-профиль (имя установки, обычно admin) сохранён.
- Отдельные имя пользователя и пароль для Redis-сервиса или инстанса.
- Независимая авторизация Sentinel: без пароля / пароль / пользователь и пароль.
- Отдельные TLS-параметры Redis и Sentinel, CA/SNI и клиентские сертификат/ключ.
- Дополнительные точные адреса Sentinel и необязательное имя master-группы.
- Раздельные состояния ошибок доступа и подсказки на русском и английском.
- Английский слоган: **All your Redis. One place.**
- Захват трёх картинок за ботву, чуть выше основания, с покачиванием.
- README и скриншоты с демонстрационными данными.
- Тесты и воспроизводимый отчёт.

Старые профили совместимы: Sentinel без авторизации таким и остаётся, Redis admin продолжает использовать общий пароль сессии. Заново добавлять все кластеры не требуется.

## Применение в локальном Git-репозитории

Перед распаковкой сохраните или закоммитьте собственные изменения. Обновление заменяет перечисленные в `docs/CONNECTIONS_R1_MANIFEST.json` файлы, включая README. Другая локальная версия тех же файлов требует сравнения через Git. Архив не содержит `.git`, LICENSE, NOTICE, workflow CI, реальные конфигурации, базу каталога, пакеты или приватные ключи.

Команды выполняются **без sudo** в корне репозитория. Путь к скачанному архиву замените фактическим:

```bash
git status --short
tar -xzf /path/to/redis-farm-0.2.0-connections-r1.tar.gz --strip-components=1
git diff --stat
git diff -- redis_farm/models.py redis_farm/credentials.py README.md README.ru.md
```

Упаковка сохраняет `tests/fake_cli.py` исполняемым. Для Git также проверьте:

```bash
git add README.md README.ru.md CHANGELOG.md redis_farm tests tools/render_demo.py docs
git update-index --chmod=+x tests/fake_cli.py
git diff --cached --stat
git diff --cached --name-only
```

После проверки:

```bash
git commit -m "Add independent Redis and Sentinel access profiles"
git push origin main
```

Если GitHub уже содержит новые коммиты, сначала согласуйте ветки; не используйте `push --force`. Опубликованный тег `v0.2.0` не перемещается от обычного коммита. Уже выложенные Assets также сами не меняются. Обновление рабочей ветки и публикация следующего архива — отдельные действия.

## Проверка исходников

```bash
python3 tools/test_all.py
node --check redis_farm/static/app.js
node --check redis_farm/static/images.js
```

Для запуска полного набора HTTP-тестов нужен Flask из зависимостей проекта. Для UI-проверок нужны Jinja2, Playwright и Chromium:

```bash
python3 tools/render_demo.py
```

Скриншоты генерируются с настоящими шаблонами, JavaScript и иллюстрациями, но с подменёнными API-ответами. Скрипт не опрашивает Redis/LDAP.

## Обновление работающего сервера

Наложение файлов в локальный Git-репозиторий **не меняет установленную службу**. На сервер передайте обновлённые исходники целиком и из их корня выполните:

```bash
sudo bash install-server.sh --skip-apt
```

Используется прежний установщик; зависимостей не добавлено. Он создаёт новую директорию релиза, сохраняет конфигурацию, каталог, сертификат и переключает `current` только после своих проверок. Не копируйте этот неполный архив поверх `current` на работающем сервере: смесь загруженных старых модулей и новых файлов до перезапуска нежелательна.

Перед обновлением сохраните конфигурацию и экспорт каталога в закрытой резервной копии, не в публичном Git-репозитории. Завершите работу в консолях: перезапуск панели закрывает её клиентские процессы и очищает пароли сессий. Удалённые Redis/Sentinel не перезапускаются.

После установки обновите страницу Ctrl+F5. В интерфейсе версия остаётся 0.2.0; новые файлы CSS/JS имеют суффикс `connections1` для обновления браузерного кеша.

## Где настраивать доступ

Откройте сервис → **Настройки подключения**. Выберите Redis/Sentinel, затем весь сервис или конкретный адрес. Глобальный Redis-профиль остаётся выбранным по умолчанию у старых записей; для другого пользователя выберите «Пользователь и пароль». В Sentinel нет варианта заимствовать глобальный Redis-пароль.

Пароль вводится только для текущей веб-сессии. Имена и TLS-пути — метаданные общего каталога. Подробные сценарии — в [CONNECTION_PROFILES.md](CONNECTION_PROFILES.md). Проверки и ограничения — в [TEST_REPORT.md](TEST_REPORT.md).

Новый общий профиль для всех сервисов Sentinel пока не реализован: каждый сервис хранит свои реквизиты в памяти сессии. Защищённый ручной порт требует явного типа Redis/Sentinel; сканирование ноды использует раздельные диапазоны. Редиректы `redis-cli -c` и ручной `CONNECT` по-прежнему находятся за пределами резолвера панели.

**Живые Redis, Sentinel, LDAP, Firefox и установка на вашем сервере в среде подготовки не проверялись.** Архив не следует считать уже установленным или опубликованным.
